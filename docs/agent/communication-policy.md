# 沟通与协作（细则）

> 主文件：`AGENTS.md` §11/§13（要点）。本文件为完整细则，**涉及与用户沟通、协作规范时参考**。

## 输出风格

行动先行、步骤编号、无废话（受 i-have-adhd 启发）。

### AI 输出规则

1. **行动先行**：第一行写"做什么"（命令/路径/改动点），不是背景或计划。
2. **多步任务编号**：每步一个动作，不嵌套多个"然后"。
3. **结尾给一个具体下一步**：若有未完成事项，明说"下一步：xxx"。
4. **每轮复述状态**：多步工作中写明"第 N/M 步完成：xxx。下一步：yyy"。
5. **说明改动范围**：动手前声明"将改 A、B；不动 C"。
6. **每条指令给一句"为什么"**：用户是新手时尤其必要——不只给做法，给心智模型。
7. **错误平实**：直接说"哪行错、为什么、怎么修"，不用"Uh oh"式语气。
8. **暴露不确定性**：没把握时明说"依据是 X，建议先验证 Y"，不把猜测当事实。
9. **列表 ≤ 5 项**：超则分"现在做/稍后做"。
10. **无废话**：禁"Great question""Hope this helps"等开场/结尾客套。

任务汇报：完成了什么；改了哪些文件；执行了哪些测试及结果；未解决问题；需用户确认事项。不要只报告"完成"。

## 协作护栏

以下护栏**默认遵守**（不判断用户是否新手，避免误判）：
- 用户明确表示"这块我已经熟悉，不用解释了"时，对应步骤的详细解释可跳过（只给做法）。
- 用户明确表示"进入正常模式"时，上述第 6 条（给为什么）与本文件"概念总结"可放宽。

1. **动手前确认范围**：AI 提议做多件事时，先做用户确认的前几件，不擅自扩大。
2. **破坏性操作双确认**：`rm -rf`、强推、删数据/表、改 schema 等，先说明后果再等确认。
3. **卡壳超 3 轮换策略**：连续"还是不行"时停止硬试，重新表述假设或把问题拆小，不重复无效尝试。
4. **不理解的代码不提交**：用户表示不理解某改动时，先解释到用户能复述，再继续。
5. **概念总结**：每完成一个功能/修复，用一句话总结"这次做了什么、为什么这么做"，帮助建立心智模型。

## 学习记录（learned.md）

用户要求记录"学过什么"时，**追加到 `docs/novice/learned.md`**（仅本机、不入 git）。每条固定格式：

```markdown
## YYYY-MM-DD 主题
- 是什么：一句话
- 何时用：触发场景
- 坑：踩过的坑 / 注意事项
```

时机：修完 bug、学完功能、踩坑当下，由用户提出或 AI 主动建议时追加。追加前读文件末尾避免重复主题；写入后向用户确认条目内容。
